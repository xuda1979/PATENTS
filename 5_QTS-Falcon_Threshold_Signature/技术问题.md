## 一、创新性与新颖性相关问题

### 问题 1：这个专利的核心创新点是什么？和现有的门限签名方案相比，区别在哪里？

**答：** 本专利有四个核心创新点：

1. **零通信 NTT 计算**：利用数论变换（NTT）的线性同态特性，各节点对私钥分片独立执行 NTT 变换，全局变换等价于各分片变换之和（$\text{NTT}(\sum [f]_i) = \sum \text{NTT}([f]_i)$），实现了多项式乘法阶段零通信开销，这是现有通用 MPC 方案（如 SPDZ）无法做到的。

2. **方差保持分布式高斯采样**：每个节点使用缩放参数 $\sigma/\sqrt{N}$ 独立采样，基于高斯卷积定理，聚合后严格服从目标分布 $D_{\sigma, R}$，统计距离 $< 2^{-128}$。无需节点间交互即可保证采样正确性。

3. **常数轮协作拒绝采样**：通过离线预生成 Beaver 三元组 + 在线承诺-揭示协议，将在线签名阶段固定为 **6 轮通信**，不随节点数增长。传统方案通信轮数为 $O(n)$。

4. **签名格式完全兼容**：输出的门限签名与标准 Falcon 签名格式完全一致（Falcon-512 约 666 字节），验证方无需任何修改即可验证，做到了"门限透明"。

与现有方案的核心区别：
- 与 Threshold Dilithium 相比：签名尺寸缩小 72.5%（666 vs 2420 字节），签名速度快 1.69 倍
- 与通用 FHE 门限方案（Boneh et al., CRYPTO 2018）相比：避免了将高斯采样放入 FHE 引擎，计算开销大幅降低
- 与经典 Threshold ECDSA（GG20）相比：具备抗量子攻击能力，速度快约 5.7 倍

### 问题 2：Falcon 的门限签名，学术界有没有已有方案？你们的方案和学术界方案的区别是什么？

**答：** 目前学术界针对 Falcon 的门限化研究极少，主要难点在于 Falcon 签名过程中涉及：
- 复杂的 FFSampling（快速傅里叶采样）树结构
- 基于 NTRU 格的离散高斯采样
- 拒绝采样（Rejection Sampling）机制

现有相关工作主要集中在 Dilithium 的门限化（如 Cozzo & Smart, 2019 的 LUOV/Dilithium 门限方案），以及 Damgård 等人（PKC 2021）基于 Fiat-Shamir with Aborts 的格多签名方案，但这些都不针对 Falcon 的 NTRU 结构。

**我们方案的独特贡献**在于：专门针对 Falcon/NTRU 代数结构设计了分布式密钥生成（MPC-XGCD 求解 NTRU 方程 $fG - gF = q$）和分布式高斯采样方案，而非使用通用 MPC 框架"暴力"门限化，因此效率远优于通用方案。

### 问题 3：NTT 的线性同态性质是公知的，你们利用这个性质做分布式计算算不算创新？

**答：** NTT 的线性性质本身确实是公知的数学性质。但本专利的创新并非在于发现这个性质，而在于：

1. **将其系统性地应用于 Falcon 门限签名的完整流程**，包括密钥生成、签名计算、拒绝采样等全链路，形成了一个完整的技术方案
2. **与方差保持高斯采样、Beaver 三元组拒绝采样相结合**，解决了 Falcon 门限化中高斯采样和拒绝采样两个核心难题
3. **实现了"零通信 NTT"优化**，将多项式乘法的通信成本从 $O(n)$ 降至 $O(0)$，这是一个系统级的工程创新

专利保护的是这些公知技术要素的**新颖组合方式**及其在特定应用场景下的**系统级解决方案**，这符合专利法对创造性的要求。

## 二、技术方案可行性问题

### 问题 4：方差保持高斯采样的数学原理是否严格成立？有什么前提条件？

**答：** 严格成立，基于以下数学推导：

如果 $n$ 个独立随机变量 $z_i \sim D_{\sigma_i, R}$（离散高斯分布），那么 $z = \sum z_i$ 服从 $D_{\sigma, R}$，其中 $\sigma^2 = \sum \sigma_i^2$。

当每个节点使用 $\sigma_i = \sigma/\sqrt{N}$ 时：
$$\text{Var}\left(\sum [z]_i\right) = \sum \text{Var}([z]_i) = N \cdot \left(\frac{\sigma}{\sqrt{N}}\right)^2 = \sigma^2$$

**前提条件**：
1. 各节点的采样必须是**统计独立**的（通过独立的 CSPRNG 种子保证）
2. 各节点必须使用**正确的缩放参数** $\sigma/\sqrt{N}$（通过可验证秘密共享模块确保）
3. 离散高斯分布对卷积定理的适用性需要 $\sigma$ 足够大（Falcon 参数 $\sigma = 165.74$ 完全满足）

统计距离分析表明：聚合分布与理想分布的统计距离 $\Delta < 2^{-128}$，满足 128 位安全参数要求。

### 问题 5：Beaver 三元组的预处理方案，离线阶段的开销有多大？是否会成为瓶颈？

**答：** 
- 离线阶段每个签名的摊销预处理时间约 69.3 ms（包括三元组生成 48.2 ms + OT 扩展 12.4 ms + 验证 8.7 ms）
- 但由于离线预处理可以在空闲时段批量执行（如一次生成 1000 组），所以对在线签名性能影响很小
- 在线签名阶段仅 6 轮通信，耗时约 12-22 ms（取决于节点数配置）

三元组存储开销：每个三元组约需要 3 个环元素的存储空间，对于 Falcon-512 约 3 KB。若预存 1000 组，总共约 3 MB，完全在可控范围内。

**不会成为瓶颈**，因为：
1. 离线计算与在线签名完全解耦
2. 可利用系统空闲时间批量预处理
3. 使用后量子安全的 OT 扩展（基于 Kyber-KEM），预处理本身也是量子安全的

### 问题 6：6 轮常数通信是怎么做到的？具体每一轮做什么？

**答：** 6 轮协议具体如下：

| 轮次 | 操作 | 内容 |
|------|------|------|
| 第 1 轮 | 承诺广播 | 各节点广播 $C_i = H(m_i \| [s]_i)$，锁定签名分片 |
| 第 2-3 轮 | Beaver 乘法 | 利用预处理三元组计算交叉项内积 $\langle[s]_i, [s]_j\rangle$（2 轮完成所有 $\binom{n}{2}$ 个交叉项） |
| 第 4 轮 | 范数揭示 | 聚合并公开全局范数 $\|s\|^2 = \sum_i \|[s]_i\|^2 + 2\sum_{i<j}\langle[s]_i, [s]_j\rangle$ |
| 第 5 轮 | 分布式抛币 | 生成共享随机数 $u$，判定接受概率 $p = M^{-1} \cdot \exp(-\langle s, c \rangle / \sigma^2)$ |
| 第 6 轮 | 分片揭示 | 签名被接受后，各节点揭示 $[s]_i$，验证一致性并聚合 |

关键技巧：**第 2-3 轮虽然需要计算 $O(n^2)$ 个交叉项，但通过 Beaver 三元组将所有乘法并行化为 2 轮广播操作**，而非逐对串行计算。

## 三、应用场景与价值问题

### 问题 8：这个方案的应用场景是什么？和中国移动的业务有什么关系？

**答：** 本方案主要面向以下场景：

1. **量子计算网络节点认证**（核心场景）：随着中国移动布局量子通信和量子计算网络，多个量子计算节点需要通过经典网络互联协作。这些节点本身具备量子计算能力，传统 ECDSA/RSA 认证在量子环境下不安全，本方案提供抗量子攻击的分布式节点认证。

2. **5G/6G 网络基础设施安全**：网络核心设备（如基站、核心网元）的密钥管理，通过门限机制避免单点密钥泄露，同时保障后量子安全。

3. **物联网设备群组认证**：大量 IoT 设备的群组签名/认证场景，门限机制使得即使部分设备被攻破，系统整体安全不受影响。

4. **跨链/分布式系统**：移动数字资产、数字身份等区块链应用中的跨链桥安全。

**与中国移动的关联**：
- GSMA 已将后量子密码迁移列为运营商安全路线图的重点
- 中国移动在量子通信（如"量子密话"）领域有布局，本方案可作为量子安全通信基础设施的认证组件
- 分布式密钥管理适用于运营商多地容灾部署架构

### 问题 10：量子计算机要威胁现有密码体系，目前看还需要多久？现在做这个是不是太早了？

**答：** 不早，原因如下：

1. **"现在截获，以后解密"（Harvest Now, Decrypt Later）威胁**：攻击者可以现在截获加密通信，等量子计算机成熟后再解密。对于长生命周期的数据（如运营商用户身份信息、政府通信），现在就需要后量子保护。

2. **标准化进程已经完成**：NIST 已于 2024 年正式发布后量子密码标准（包括 Falcon），说明国际社会认为迁移窗口已经打开。

3. **量子计算进展加速**：IBM、Google、中国科学技术大学等已展示超过 1000 量子比特的处理器。虽然破解 RSA-2048 可能需要数百万逻辑量子比特，但技术演进的不确定性要求提前布局。

4. **迁移周期长**：密码体系迁移通常需要 5-10 年。运营商网络设备量大面广，越早启动越主动。

5. **国家政策要求**：国家密码管理局已发布后量子密码迁移相关指导意见，运营商作为关键信息基础设施需要提前准备。

## 四、安全性问题

### 问题 11：如何防止恶意节点在签名过程中作弊？

**答：** 本方案通过多层安全机制防止恶意节点：

1. **可验证秘密共享（VSS）**：密钥生成阶段，每个节点必须广播对其分片的承诺并提供零知识证明，确保分片的正确性。

2. **承诺-揭示协议**：签名阶段，节点先广播承诺 $C_i = H(m_i \| [s]_i)$，再揭示签名分片。这防止了恶意节点在看到其他节点结果后修改自己的分片。

3. **Beaver 三元组验证**：通过"牺牲"协议（sacrifice protocol）验证预生成三元组的正确性，错误概率 $< 2^{-40}$。

4. **门限容错**：(t, n) 门限结构下，只要诚实节点 ≥ t，系统安全性不受影响。例如 (5,7) 配置下最多可容忍 2 个恶意节点。

5. **前向/后向安全**：支持份额刷新（Share Refresh），即使过去或未来某个时刻节点被攻破，不影响当前签名的安全性。

---

### 问题 12：分布式高斯采样会不会泄露私钥信息？

**答：** 不会，安全性由以下机制保证：

1. **信息论安全的秘密共享**：任何 $t-1$ 个节点的分片组合，对完整私钥的信息泄露为 **0 比特**（信息论意义上的安全）。

2. **零知识性**：拒绝采样机制确保最终签名的分布与"不使用私钥生成的模拟签名"在统计上不可区分。形式化证明见技术规格书中的定理 3.2（t-Privacy）。

3. **独立采样**：各节点独立使用本地 CSPRNG 采样，采样值不在网络上传输，只传输承诺和最终分片。

4. **EUF-CMA 安全**：系统在选择消息攻击下具有存在性不可伪造性（Theorem 3.1），即攻击者即使获得多项式多个签名样本，也无法伪造新签名。

### 问题 21：有没有考虑和国密算法（SM2/SM9）的兼容性？

## 九、其他可能的尖锐问题

### 问题 22：你们说在线签名只需要 12-22ms，但 Falcon 单签名者就要 42ms，门限反而更快了？这合理吗？

**答：** 这是一个很好的问题。需要澄清：

- 42 ms 是**纯 Python 参考实现**的单签名者性能（在 32 位 Python 3.13 上测量）
- 12-22 ms 是基于 **Rust/C++ 优化实现 + 专用硬件**的门限签名估算
- 两者的计算基准不同

如果使用相同的优化实现：
- 优化后的 Falcon 单签名者约 **2-5 ms**
- 门限签名的在线阶段额外开销主要来自 6 轮网络通信（约 2.5 ms × 6 = 15 ms RTT）+ Beaver 乘法（约 3-4 ms）
- 因此门限签名总延迟约为 **20-25 ms**，相比单签名者慢约 4-5 倍

这一开销在可接受范围内，且已是当前已知的最优方案。

### 问题 23：为什么选 (t,n) 加法秘密共享而不是 Shamir 秘密共享？

**答：** 本方案使用加法秘密共享（Additive Secret Sharing）而非 Shamir 秘密共享，原因：

1. **NTT 线性兼容**：加法秘密共享与 NTT 的线性同态直接兼容（$\text{NTT}(\sum [f]_i) = \sum \text{NTT}([f]_i)$），而 Shamir 共享使用拉格朗日插值，在 NTT 域不直接适用。

2. **乘法更高效**：加法共享下的乘法只需 Beaver 三元组（常数轮），Shamir 共享下的乘法需要度缩减（degree reduction），通信更复杂。

3. **环结构适配**：Falcon 工作在多项式环 $R_q = \mathbb{Z}_q[X]/(X^n+1)$ 上，加法共享在环上自然定义，而 Shamir 共享在环上的定义和安全性分析更复杂。

4. **实际的 (t,n) 门限**：通过结合可验证秘密共享（VSS）和动态节点管理，加法共享方案也能实现任意 (t,n) 门限功能。

### 问题 24：节点掉线或新节点加入时，系统如何处理？

**答：** 本方案支持动态节点管理：

1. **节点掉线**：只要在线诚实节点数 ≥ t，签名仍可正常进行。缺席节点的份额可通过其他节点协作重构（利用 NTRU 格的代数特性）。

2. **新节点加入**：通过 Share Refresh（份额刷新）协议，现有节点协作为新节点生成有效分片，无需重新生成密钥或更改公钥。

3. **份额刷新**：支持主动式安全（Proactive Security），定期刷新所有节点的份额。即使攻击者在不同时间窗口分别攻破不同节点，也无法拼凑出完整私钥。

4. **通信开销**：份额刷新需 $O(n^2)$ 通信，门限变更为 $O(1)$，均在可控范围内。

### 问题 25：这个方案和量子密钥分发（QKD）有什么关系？能否结合使用？

**答：** 

本方案与 QKD 是互补关系：
- **QKD** 解决的是密钥分发的信息论安全性（利用量子力学原理）
- **本方案** 解决的是身份认证和签名的计算安全性（基于格困难问题）

两者可以结合使用：
1. QKD 提供量子安全的对称密钥作为节点间安全通信的基础
2. 本方案的门限签名提供量子安全的身份认证和不可否认性
3. 组合方案可实现 "量子安全密钥分发 + 量子安全身份认证" 的完整安全架构

这对于中国移动已有的量子通信网络（如"量子密话"业务）是很好的技术延伸。
