\section*{四、分析评述}

\subsection*{（一）本申请方案的必要技术特征拆分（用于对照）}

为便于与现有技术逐项比对，将本申请方案的关键必要技术特征拆分如下（编号仅用于检索与评述）：

\begin{itemize}[leftmargin=2em]
    \item \textbf{F1 会话内动态跳频：}面向安全网关/SEPP/TLS或IPsec保护链路，在同一会话内部按时间片、$\SeqID$或记录号对机密性相关密码原语进行动态轮换，并区分用于会话种子建立或刷新的KEM跳频（Macro模式）与用于逐记录/逐包封装的DEM/AEAD跳频（Nano模式）。
    \item \textbf{F2 确定性无状态派生：}接收端仅依据$\SeqID$（或时间片）、会话种子与模式盐值即可独立恢复当前受保护单元的算法索引与单元密钥，容忍乱序/丢包，无需依赖前序运行状态。
    \item \textbf{F3 正交安全约束：}仅对承担会话种子建立或刷新作用的KEM类别施加正交约束。当前实施例的机密性类别为Lattice-S、Lattice-U、Code，并要求相邻受保护单元满足"类别距离$\ge d_{\min}$"；签名原语不纳入机密性距离矩阵。
    \item \textbf{F4 过渡重叠窗口与降级攻击防御：}在切换点设置过渡重叠窗口与双解码策略；一旦成功处理新算法单元即关闭旧窗口，用于兼顾乱序网络下的可用性与降级攻击防御。
    \item \textbf{F5 可选HED阈值分片：}对同一原始载荷可选执行$(k,n)$阈值分片/纠删码分散，并施加对象级类别配额，使任一KEM类别在同一对象中的份额数受限。
    \item \textbf{F6 可选MPTD多路径分散：}将不同受保护单元或HED份额映射至不同物理路径或子流，实现与算法轮换协同的安全分散。
\end{itemize}

\subsection*{（二）与主要现有技术方案的对比分析}

基于检索到的相关文献（专利P1--P3，非专利N1--N5/S1--S6/R1--R2），现有技术路线与本申请方案的核心差异可以概括为：现有标准协议（如TLS 1.3、QUIC）主要支持会话级算法协商或同一算法套件内的密钥更新，缺少面向记录/包级受保护单元的跨算法动态轮换（F1）与KEM类别正交约束（F3）；后量子标准化与迁移方案（如NIST相关标准、3GPP TR 33.875）主要聚焦于算法替换、版本迁移与治理策略，缺少会话内动态轮换和对象级类别配额机制；Signal双棘轮实现了每消息密钥演化，但算法保持固定，且对状态推进存在依赖，不能直接对应本申请的F2；KEM Combiners属于静态并行组合，而非序列化轮换；多路径传输协议（如MPTCP）主要解决性能与可靠性问题，未形成与算法跳频、HED联动的安全分散框架。综合比较后，最接近专利P1（US20230058198A1）仅对F1构成部分覆盖，未涉及F2--F6的核心组合。详细逐特征覆盖对比见下表。

\section*{五、检索结论}

基于初始检索（2026.01.26）以及2026.02.12、2026.03.24两轮补充复核检索，对包括RFC标准、IETF草案、专利文献及经典密码理论等文献的全面检索与分析，结论如下：

    \textbf{未检索到X级（特别相关）文献}：在本次检索范围内，未发现单一公开文本同时覆盖本申请的“面向安全网关/SEPP/TLS-IPsec链路的会话内动态跳频（F1）”“受保护单元级确定性无状态派生（F2）”“基于KEM困难问题类别的正交约束（F3）”“过渡重叠窗口（F4）”以及“可选HED/MPTD联动（F5/F6）”等组合特征，因此不存在足以单独破坏本申请新颖性的X级文献。

现有技术主要存在以下局限：

\begin{itemize}[leftmargin=2em]
    \item 已公开方案多停留在握手/安全上下文建立阶段的算法协商、版本迁移或静态混合，缺少会话内面向记录或包级受保护单元的动态轮换机制（F1）。
    \item 即使存在动态算法或动态通信信道方案，也未将$\SeqID$无状态派生、KEM类别正交约束以及SEPP/PQSG/TLS/IPsec链路中的网关实现结合为同一体系（F2/F3/F4）。
    \item 阈值分片或多路径机制若单独存在，多以传输可靠性或一般分散为目的，缺少对象级类别配额和与算法跳频协同的安全分散框架（F5/F6）。
\end{itemize}

    \textbf{综上所述}，在本次检索范围内，最接近现有技术为P1（US20230058198A1），其仅对F1构成部分覆盖；P2（CN114640455B）对动态加密/动态信道具有启发但未触及F2--F6核心组合；P3（CN119450460A）停留在安全算法选择/协商层面。未发现单一公开文献同时公开F1--F6的组合，尤其未发现“受保护单元级无状态派生 + KEM类别正交约束 + 安全网关/跨域接口落地架构 + HED/MPTD联动”的整体方案，因此\textbf{本申请具有较明确的新颖性与创造性论证基础}。具体而言：

\begin{itemize}[leftmargin=2em]
    \item \textbf{F2（无状态派生/乱序容忍）与F4（过渡重叠窗口/双解码）并非简单拼接：}其需要在允许乱序和重传的网络条件下同时满足解密成功率、重放检测与密钥更新一致性，属于记录层/包级保护链路中的工程约束体系。
    \item \textbf{F3（KEM困难问题类别正交约束）区别于一般“支持多算法/可配置”的密码敏捷：}本申请仅对承担机密性种子建立或刷新作用的KEM类别建模，当前实施例采用Lattice-S、Lattice-U、Code三类，并以“类别距离$\ge d_{\min}$”约束相邻受保护单元，使该规则能够在工程实现中转化为可执行、可审计的调度约束。
    \item \textbf{F1/F2/F3与SEPP/PQSG/TLS/IPsec链路嵌合后形成具体产品形态：}该方案能够直接对应跨域接口保护设备、安全网关和安全代理的报文处理链路，具备明确的应用对象和可落地实施路径，而非脱离应用场景的抽象算法构思。
\end{itemize}
