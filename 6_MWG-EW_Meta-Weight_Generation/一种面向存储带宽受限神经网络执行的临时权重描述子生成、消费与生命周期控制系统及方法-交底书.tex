\cmdisclosuresection{一、发明名称}
\cmdisclosurepara{一种面向存储带宽受限神经网络执行的临时权重描述子生成、消费与生命周期控制系统及方法。}

\cmdisclosuresection{二、技术领域}
\cmdisclosurepara{本申请涉及人工智能推理、神经网络训练、Transformer 模型执行优化、分布式训练通信控制和模型压缩领域，尤其涉及一种在 GPU、NPU、TPU 及其他 AI 加速器上执行的神经网络执行系统和方法。更具体地，涉及一种在前向执行或反向传播过程中根据条件信号实时生成临时权重描述子块，在片上局部存储器中完成生成后消费，并在全生命周期内阻止其完整物理形态写回外部存储器的执行机制。}

\cmdisclosuresection{三、现有技术的技术方案}
\cmdisclosurepara{在大语言模型和其他 Transformer 模型中，大量参数集中于前馈网络块以及其他目标线性变换层。推理时，这些矩阵通常以静态稠密权重的形式保存在外部存储器中，并在每层、每个 token 的计算中被反复读取到片上资源。训练时，除了前向读取外，还需要在反向传播中再次使用这些权重完成梯度计算，并为对应梯度维护优化器状态以及跨节点同步通信。}
\cmdisclosurepara{随着矩阵计算单元吞吐不断提升，而高带宽显存、片外存储和节点间通信带宽的提升相对有限，系统越来越容易受到权重搬运、优化器状态访问和 All-Reduce 通信的限制，形成外部存储与网络双重瓶颈。现有技术通常通过以下方式改进：1．量化，降低单位权重位宽；2．剪枝或静态低秩压缩，减少持久参数规模；3．LoRA 或其他参数高效微调方法，降低训练参数规模；4．Mixture-of-Experts，通过稀疏激活减少有效计算量；5．Hypernetwork 或动态滤波器方法，根据输入生成权重或滤波核；6．IO-aware kernel 或 SRAM 常驻加速器设计，降低中间结果与权重的外存访问；7．ZeRO、分片优化器或其他训练系统，用于压缩优化器状态和同步流量。}

\cmdisclosuresection{四、现有技术的缺点及本申请要解决的技术问题}
\cmdisclosurepara{上述现有技术虽能分别从位宽压缩、静态参数裁剪、稀疏激活、动态生成或训练系统优化等角度降低部分开销，但仍未解决一个更根本的问题：目标层权重在系统实现中仍被当作需要长期驻留、可被回写并需参与训练全链路管理的持久对象。由此带来以下不足：1．量化和静态低秩压缩仍默认权重为持久参数，执行时仍需从外部存储器读取；2．Hypernetwork 类方法通常强调“生成权重”这一概念，但未突出片上局部存储器中的分块生命周期控制；3．SRAM 常驻或 IO-aware kernel 类方案通常默认权重事先存在，并未解决运行时临时生成与即时销毁的问题；4．分布式训练优化更多聚焦梯度压缩或状态分片，未把“运行时临时生成的权重分块不进入优化器状态也不同步”作为统一执行约束。归纳而言，现有技术缺少一个把“生成、驻留、消费、释放以及训练通信处理”统一起来的权重对象生命周期控制机制。}
\cmdisclosurepara{因此，本申请要解决的技术问题是：如何建立一种统一的底层执行架构，使目标线性变换在前向执行、解码推理和训练反向传播中均不依赖外部存储器反复读取完整稠密权重矩阵，而是通过片上生成、片上消费、用后销毁和训练通信截断的方式，把权重对象从“外存中的持久矩阵”改造成“执行期间受控存在的临时对象”，从而同时降低外部存储流量、解码缓存压力以及跨节点同步负担。}

\cmdisclosuresection{附：评审关注问题速览}
\cmdisclosurepara{为便于评审人在较短时间内形成判断，可优先看以下六个问题的直接答案。本申请的论证重心不是抽象地强调“生成权重”，而是把“外部存储持续搬运的大矩阵”改造成“按条件在片上生成、片上消费、用后销毁且不回写的临时对象”，并围绕这一物理对象管理闭环组织前向、解码、训练和取证论证。}
\cmdisclosurepara{\textbf{评审关注点1：现有技术存在什么问题。} 现有方案即使采用量化、静态低秩压缩、LoRA、MoE 或 IO-aware kernel，通常仍把目标权重视为需要长期保存和反复搬运的持久对象，因此仍然面临外部存储带宽压力、解码缓存挤占以及训练阶段优化器状态和跨节点同步负担。换言之，现有技术大多在“怎样把权重存得更省”或“怎样把计算做得更快”上优化，但没有把“权重对象本身不再作为外存持久矩阵存在”落成统一的系统执行约束。}
\cmdisclosurepara{\textbf{评审关注点2：有没有可靠数字说明这个问题的量级。} 可以。按 fp16、\(d=4096\)、\(m=14336\) 的解析估算，单个 FFN 投影若按稠密矩阵存储，需要 \(2dm=117{,}440{,}512\) 字节，即约 112 MiB；门控 FFN 的上投影、门控投影和下投影三者合计约 \(352{,}321{,}536\) 字节，即约 336 MiB。若采用秩 \(r=64\) 的低秩描述子表示，则单投影约 \(2{,}359{,}296\) 字节，约 2.25 MiB，三投影块约 \(7{,}077{,}888\) 字节，约 6.75 MiB，对应目标投影对象的理论字节量约下降 49.8 倍；当 \(r=128\) 时，对应目标投影对象的理论字节量仍约下降 24.9 倍。上述数字基于矩阵维度的解析计算，用于说明问题规模和技术效果的数量级，并不等同于整模型端到端吞吐、整机显存占用或系统级真实收益的实测结果。}
\cmdisclosurepara{\textbf{评审关注点3：本申请解决问题的核心技术手段是什么，以及创新性在哪里。} 本申请的核心技术手段是：根据至少包括激活特征表示和层标识的条件信号，由元生成器在执行时生成临时权重描述子块；所述描述子块只允许在片上局部存储器中驻留，由融合执行引擎在片上完成转换、重构或结合式矩阵执行，并在当前块计算结束后立即释放、覆写或清零，且在全生命周期内禁止其完整物理形态写回外部存储器。创新性不在于单独提出 Hypernetwork、低秩分解或 kernel fusion，而在于把“运行时条件生成、片上驻留、即时消费、用后销毁、不回写外存、可选反向重算和同步截断”组织成同一执行闭环，使创新点落在可工程实施的对象生命周期控制和数据流约束上。}
\cmdisclosurepara{\textbf{评审关注点4：交底书描述是否清楚充分。} 当前文本已经披露了目标对象定义、模块边界、条件输入、生命周期状态、前向/解码/训练三类处理流程、负面限定、不回写约束、平台泛化术语、可选实施方式以及外部可观测特征，并配置了七张示意图辅助理解。若后续需要进一步增强授权和答审弹性，可补充 profiler 结果、HBM 流量对比、训练恢复曲线和同步抓包数据，使技术效果同时具备解析支撑和实测支撑。}
\cmdisclosurepara{\textbf{评审关注点5：方案的运用前景如何，偏自用还是他用。} 二者兼具。自用场景包括中国移动内部大模型训练集群、云侧推理服务、边缘推理节点、AIDC 资源调度平台以及需要降低显存或带宽成本的 AI 基础设施；他用场景包括向 AI 芯片厂商、服务器整机厂商、云服务商、模型框架厂商和推理引擎提供运行时组件、编译器优化模块、驱动/固件能力或联合解决方案。该方案主要改造软件栈、运行时、编译器、驱动和片上存储管理逻辑，不以全新工艺路线或全新硬件架构为前提，因而具备较清晰的产业化落地路径，工程迁移成本也相对可控。}
\cmdisclosurepara{\textbf{评审关注点6：如果最终形成产品，侵权取证能不能获取。} 相对于纯算法类方案，本申请的取证入口更偏向可观测的系统执行特征，包括：目标层外部存储器读写字节显著低于稠密基线理论下限、矩阵计算单元保持较高利用率而访存 stall 下降、解码场景中可用外部存储容量向键值缓存重分配、训练场景中目标层 All-Reduce 或等效同步数据包明显减少甚至缺失。上述特征可结合标准 profiler、硬件性能计数器、网络抓包工具、公开开发者文档、性能白皮书和对外宣传口径交叉验证；其取证效果仍取决于产品开放程度、可测接口和可获取样机或服务形态。}

\cmdisclosuresection{五、本申请的技术方案的详细阐述}
\cmdisclosurepara{为了便于评审快速把握本申请的技术工作方式、相对既有技术的区别以及工程价值，可将本方案概括为以下一句话：把原本需要长期保存在外部存储器并参与训练全链路管理的权重矩阵，改造成按条件信号在片上运行时生成、片上转换、立即消费、用后释放且全生命周期不回写的临时对象；由此可带来外部存储访问减少、解码可用缓存增加和训练同步量下降，并可通过软件栈、运行时、固件或控制逻辑的形式落地到现有 AI 加速器平台。}
\cmdisclosurepara{本申请的核心技术手段是：不再将目标线性变换的完整稠密权重矩阵作为必须长期存在于外部存储器中的操作数，而是通过元生成器在执行时根据条件信号生成临时权重描述子块，并由融合执行引擎在片上局部存储器中直接将其转换为临时目标权重分块或者等效因子分块后立即消费。所述条件信号至少包括激活特征表示和层标识，可选还包括序列位置嵌入、序列长度信息、路由摘要、任务标识、领域标识、批统计量和硬件执行配置文件。该核心技术手段的创新性不在于单独引入“生成权重”或“低秩分解”概念，而在于把运行时生成、片上短驻、即时消费、用后释放以及全生命周期不回写组织成统一的可执行机制。}
\cmdisclosurepara{如图2所示，可将本申请的工作方式概括为一条主链路加两个可选收益分支：主链路为“激活块和层标识形成条件信号，元生成器生成临时权重描述子块，所述描述子块在片上局部存储器中短暂驻留并完成片上转换或重构，随后由矩阵计算单元立即消费，在当前块计算结束后立即释放、覆写或清零，并且禁止其完整物理形态回写外部存储器”；在此基础上，解码场景可把节省的外部存储容量转给键值缓存，训练场景可在反向时片上重算并截断优化器状态和跨节点同步。}

\cmdisclosurepara{为使技术效果具备统一、可复算的论证口径，本申请进一步采用带宽--计算协同的解析仿真对目标 FFN 块进行评估。以 fp16、\(d=4096\)、\(m=14336\) 的三投影门控 FFN 为例，稠密块理论字节量约为 336.0 MiB；若采用基库系数路径且秩值 \(r=128\)，则包含生成器摊销项后的有效读取约为 11.08 MiB，对应目标块外部存储读取约下降 30.3 倍；当 \(r=96\) 时，有效读取约 8.52 MiB，对应验证损失增量约 4.73\%；当 \(r=160\) 时，有效读取约 13.64 MiB，对应验证损失增量约 2.40\%。该组结果说明，本申请在 \(r=96\) 至 \(r=128\) 区间已经形成较优的质量--效率折中。}
\cmdisclosurepara{进一步按 FFN 替换比例扫描，在同一 80 GiB 外部存储预算下，50\% 替换时端到端批处理时延可由 4.20 s 降至 3.24 s，峰值模型内存可由 68.00 GiB 降至 55.43 GiB，可支持的键值缓存上下文由 16384 token 提升至 33547 token；当替换比例达到 100\% 时，批处理时延约为 2.27 s，峰值模型内存约为 42.86 GiB，最大上下文约为 50711 token，训练侧 All-Reduce 体积可由 1024 MiB/step 下降至 192 MiB/step。换言之，本申请并非只降低目标块读写，而是把节省的外部存储预算真实转化为解码缓存收益和训练同步收益。}
\cmdisclosurepara{在可选增强实施方式中，若对条件信号相近的 token 采用有界时间窗复用，则在 \(r=128\) 时，复用窗口由 1 提高到 4，可使有效读取由 11.08 MiB 进一步降至 10.06 MiB，批处理时延由 2.27 s 降至 2.20 s，而额外精度漂移仅约 0.6\%；在 HBM 带宽分别为 1.6、2.4 和 3.2 TB/s 的平台假设下，本方案相对稠密基线仍分别保持约 1.90 倍、1.85 倍和 1.80 倍的加速。由此可见，本申请的收益并不依赖单一硬件档位，而是在更受带宽限制的平台上更为显著。}

\cmdisclosuresection{六、本申请的关键点和欲保护点}
\cmdisclosurepara{关键点1：前向核心防御。系统在运行时根据条件信号生成临时权重描述子块，在片上局部存储器中转换为临时目标权重分块或者等效因子分块，当前块计算完成后即进入释放、覆写或清零流程，并在对应片上缓冲区被重用前完成所述流程，且在全生命周期内不将对应目标权重分块的完整物理形态写回外部存储器。该点应作为最宽根权利要求的中心。}
\cmdisclosurepara{关键点2：推理解码防御。系统用于自回归解码推理时，节省的外部存储容量动态重分配给键值缓存；同时通过至少两个缓冲区的双缓冲生成与计算重叠，覆盖超长上下文和高并发推理场景。该点建议作为第二层保护重点。}
\cmdisclosurepara{关键点3：训练与通信防御。系统在反向传播时重新在片上局部存储器中生成对应块，对应局部梯度块不进入全局优化器状态缓存，不参与多节点同步，仅同步元生成器参数、基库参数或者其他压缩参数子集。该点建议作为第三层保护重点，是与现有训练系统区分的关键。}
\cmdisclosurepara{关键点4：负面限定。应在正式权利要求中加入排他性限定，即：在当前输出块或者当前梯度块计算完成后，在片上局部存储器中对当前临时对象执行释放、覆写或清零流程，并在对应片上缓冲区被重用前完成所述流程；且在其全生命周期内，严禁将其完整物理形态写回外部全局存储器。}

\cmdisclosuresection{七、与第三条中最接近的现有技术相比，本申请有何技术优点}
\cmdisclosurepara{从评审快速理解角度看，本申请的技术优点和工程价值可归纳为三点：1．创新点是把权重对象从“外存中的持久矩阵”改造成“片上受控存在的临时对象”；2．技术提升是同时减少外部存储访问、解码缓存占用和训练同步负担，而不是只优化其中一个环节；3．工程价值是可直接落到训练框架、推理引擎、编译器、驱动、固件或芯片控制逻辑中，具备较清晰的产业化出口。}
\cmdisclosurepara{从量化效果看，在上述统一解析仿真中，三投影目标块在 \(r=128\) 时由 336.0 MiB 稠密读取降至 11.08 MiB，有效读取下降约 30.3 倍；满量替换时峰值模型内存下降约 25.14 GiB，可支持上下文由 16384 token 提升至 50711 token，训练同步体积由 1024 MiB/step 下降至 192 MiB/step。与最接近的现有技术相比，本申请的优点并非单个指标更优，而是在同一对象生命周期约束下同时带来访存、缓存和同步三类系统收益。}
\cmdisclosurepara{本申请的创新性不在于单独提出 Hypernetwork、低秩分解、片上执行或训练通信优化中的任一概念，而在于将“运行时生成的临时权重描述子块”与“片上生命周期控制、不回写、反向重算以及训练通信截断”组织成同一执行体系，使创新点落在可工程实施的对象管理和数据流控制上。}
\cmdisclosurepara{与一般 Hypernetwork 或动态滤波器技术相比，本申请并非只主张“生成权重”，而是把生成对象限定为临时权重描述子块，并进一步把其物理存储位置限定在片上局部存储器中，强调“生成、片上转换、片上消费、用后释放、全生命周期不回写”的完整执行闭环。}
\cmdisclosurepara{与 LoRA、静态低秩压缩以及参数高效微调方案相比，本申请并不把低秩因子作为持久参数长期存储于外部存储器，而是将其作为运行时生成、临时存在、用后销毁的片上对象。因此，本申请不仅改变参数规模，更改变前向和反向的数据流。}
\cmdisclosurepara{与片上常驻静态权重或 IO-aware kernel 方案相比，本申请的优化对象前移到了“权重对象本身的创建和生命周期”，不是把预先存在的静态权重搬到片上，而是在执行时即时生成并即时销毁，从而进一步降低目标层外部存储访问。}
\cmdisclosurepara{与现有训练通信优化技术相比，本申请不仅优化同步量，更把与临时权重描述子块对应的局部梯度块从优化器状态缓存和跨节点同步路径中剥离，使目标层在训练时既减少权重读取，又减少优化器状态访问和节点间通信负担。}
