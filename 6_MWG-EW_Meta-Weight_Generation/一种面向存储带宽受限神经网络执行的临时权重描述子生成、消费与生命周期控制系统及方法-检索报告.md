## 2. 拟申请方案摘要

拟申请方案的核心在于：

1. 根据至少包括 token 相关特征和层标识的条件信号，在执行时由元生成器生成权重描述子 tile；
2. 所述权重描述子优选为低秩因子或基库系数，不直接在外部存储中形成完整稠密矩阵；
3. 在前向执行或反向重算过程中采用例如 `Y = (XU)V` 的结合式矩阵分解；
4. 生成的权重描述子 tile 仅驻留在寄存器、共享内存、SRAM 或缓存等片上局部存储中；
5. 使用后立即释放、覆写或清零，不回写外部存储区域；
6. 在训练场景下，可对与所述临时对象对应的局部梯度块实施优化器状态和跨节点同步门控。

换言之，拟申请方案希望把“外存反复取 FFN 权重”的问题改造成“在片上动态生成并立即消费临时权重描述子，并在训练时按需重算”的问题。

## 5. 现有技术分项风险分析

### 5.1 “一个网络生成另一个网络的权重”

风险等级：**高**

依据：

1. N1 `HyperNetworks`；
2. N2 `Dynamic Filter Networks`；
3. P1 `Adaptable neural network`。

结论：

如果权利要求仅写成“由元生成器/超网络根据输入生成另一网络权重”，则极易被现有技术覆盖或至少显著削弱。

### 5.2 “低秩因子/低秩适配/低秩压缩”

风险等级：**高**

依据：

1. N3 `LoRA`；
2. P4 `Low-rank adaptation of neural network models`；
3. P5 `Low-Rank Compression of Neural Networks`；
4. P6 `Dynamic low-rank estimation for transformer-based language models`。

结论：

如果权利要求仅写成“使用低秩因子减少参数量或带宽”，授权空间较弱。

### 5.3 “Transformer FFN/Attention 的参数共享、剪枝、低秩”

风险等级：**中高**

依据：

1. P3 `WO2024072001A1`；
2. P4、P5、P6。

结论：

“面向 Transformer / FFN / attention 的参数优化”已是高密度竞争区，不能把新颖性押在该表述上。

### 5.4 “片上局部存储 / SRAM 常驻 / 避免外存读取”

风险等级：**中高**

依据：

1. P2 `US20240078417A1`；
2. N4 `FlashAttention`。

结论：

“把权重放在片上、减少 HBM 访问”本身也不是空白区。

### 5.5 “组合式执行生命周期”

即：

`条件生成 -> 低秩/描述子 tile -> (XU)V 结合式执行 -> 仅在片上局部存储存在 -> 用后释放且不回写外存`

风险等级：**中等，且是本方案当前最有希望的授权落点**

本次初检未发现公开文献完整披露该全组合，尤其是以下组合点同时出现：

1. 运行时条件生成；
2. 生成对象是低秩或等价权重描述子 tile；
3. 以 `(XU)V` 等结合式计算避免完整矩阵外存实体化；
4. 仅在片上局部存储生命周期存在；
5. 用后释放且不回写外存。

这里需要特别说明：

这并不意味着一定具有新颖性或创造性，只能说明**在本次初步公开检索中未直接检出完全相同的公开文献组合**。

## 6. 对拟申请方案的初步结论

### 6.1 可以继续申请，但必须收窄主张重心

综合判断，本方案**不宜**把宽泛的发明点写成：

1. “Hypernetwork 动态生成权重”；
2. “Transformer 使用低秩因子”；
3. “减少存储带宽”；
4. “将权重放到片上执行”。

这些表述单独看都已有较强现有技术压力。

### 6.2 最可主张的核心应当是

建议将独立权利要求的中心放在：

1. 加速器内存层级；
2. token/层条件信号；
3. 运行时生成权重描述子 tile；
4. 结合式 `(XU)V` 计算；
5. tile 级生成-消费-释放，以及双缓冲场景下的缓冲区重用前释放；
6. 不在外部存储中实体化完整稠密矩阵；
7. 不将生成描述子回写为持久模型权重。

### 6.3 从属权利要求可进一步覆盖

1. FFN 的上投影/门控投影/下投影；
2. 基库系数重构；
3. 单 kernel 融合；
4. 清零/覆写；
5. 自适应 rank；
6. 分组 token 复用；
7. 动态/静态混合调度；
8. 从预训练稠密模型迁移的训练流水线。

## 7. 建议的权利要求风险排序

### 7.1 风险最高的宽 claim

1. “一种由超网络生成另一网络权重的方法”
2. “一种基于低秩因子的神经网络压缩/执行方法”
3. “一种将权重放在局部存储中执行的方法”

### 7.2 中等风险 claim

1. “一种面向 Transformer FFN 的动态低秩权重生成方法”
2. “一种根据 token 条件生成 FFN 权重的方法”

### 7.3 当前最值得押注的 claim

1. “一种在加速器上执行的神经网络执行系统，其中根据 token 特征和层标识生成权重描述子 tile，并在片上局部存储中通过结合式矩阵分解消费后释放，且在执行过程中不将对应完整稠密矩阵写入外部存储”

## 9. 最终结论

截至 **2026年3月20日** 的本次初步公开文献检索表明：

1. **动态生成权重**、**低秩因子**、**Transformer 参数优化**、**片上本地权重执行** 这些单点均已有较强现有技术；
2. 本方案若想提高授权概率，必须强调**系统执行生命周期**而不是抽象算法概念；
3. 当前最可争取的技术边界，是：

`条件生成 + 低秩/描述子 tile + 结合式执行 + 片上局部驻留 + 用后释放 + 不回写外存`

4. 因此，本方案更适合作为**系统/执行路径类专利**推进，而不是作为“纯数学低秩”或“泛 hypernetwork”类专利推进。
