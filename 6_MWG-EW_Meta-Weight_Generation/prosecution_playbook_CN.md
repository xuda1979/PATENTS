# 审查与修改梯度 Playbook
# MWG-EW

---

## 1. 目的

本文件用于在正式递交申请或收到审查意见通知书后，快速确定：

1. 主张重心；
2. 哪些技术点可优先保留；
3. 哪些技术点可作为修改梯度上提；
4. 如何回应常见创造性、技术特征和客体审查类意见。

---

## 2. 当前最优主张重心

建议始终围绕以下组合主张：

1. 片上存储器与外部存储器的明确内存层级；
2. 基于激活特征表示和层标识的运行时条件生成；
3. 生成对象为临时权重描述子块，而非外部存储器中的静态完整稠密权重；
4. 临时对象在片上存储器中转换为临时目标权重分块或者等效因子分块；
5. 临时对象仅在片上存储器中驻留并被消费；
6. 使用后释放、覆写或清零；
7. 在全生命周期内不回写外部存储器；
8. 在训练场景中可进一步实施反向重算、优化器状态截断和跨节点同步豁免。

---

## 3. 不宜作为独立权利要求中心的表述

以下表述可以出现在背景技术或对比中，但不宜单独作为主权项核心：

1. “动态生成权重”
2. “Hypernetwork”
3. “低秩压缩”
4. “减少带宽”
5. “适用于 Transformer”
6. “可被 profiler 观测”

原因是这些表述要么现有技术压力较强，要么更适合作为效果或证据，而不是发明边界本身。

## 4. 修改梯度

### 第一梯度：当前主权项

当前最佳独立权利要求边界为：

`条件生成 + 临时权重描述子块 + 片上转换/消费 + 生命周期控制 + 全生命周期不回写`

适用场景：

1. 初次递交；
2. 审查员检出现有技术仅覆盖 Hypernetwork、低秩或片上常驻静态权重中的部分点。

### 第二梯度：上提单内核 / 生命周期细节

如遇到更近现有技术，可将下列特征上提至独立权利要求：

1. 单次持久化内核 启动中完成生成、消费、累积和释放；
2. 在当前块计算完成后执行释放、覆写或清零，并在对应片上缓冲区被重用前完成该流程；
3. 以块为粒度依次生成和消费。

对应来源：

1. `claims_CN_final.md` 中权利要求10、12、19；
2. `patent_spec_CN_final.md` 中分块生命周期和硬件实现实施方式。

### 第三梯度：限定推理解码场景

如审查员引用一般动态权重生成文献，可进一步限定：

1. 目标层为 Transformer 前馈网络块；
2. 分别针对上投影、门控投影和下投影生成临时权重描述子块；
3. 节省的外部存储空间动态分配给键值缓存；
4. 使用双缓冲实现生成与矩阵乘加的时间重叠。

### 第四梯度：限定训练与通信场景

如审查员引用一般训练系统文献，可进一步限定：

1. 反向传播时再次在片上存储器中生成对应块；
2. 对应局部梯度块不进入全局优化器状态缓存；
3. 对应局部梯度块不参与多节点同步；
4. 仅同步元生成器参数、基库参数或者其他压缩参数子集。

### 第五梯度：限定基库重构或自适应秩

在需要进一步区别低秩静态方案时，可加入：

1. 元生成器输出基库系数；
2. 在片上存储器中重构低秩因子；
3. 根据 token 复杂度、带宽、片上容量或时延动态调节秩值或块大小。

## 5. 常见审查意见及答复方向

### 5.1 意见类型：属于抽象算法或数学规则

答复方向：

1. 强调加速器的内存层级和向量计算单元/矩阵计算单元；
2. 强调片上存储器中的生命周期控制；
3. 强调与外部存储器读写行为、通信总线同步行为直接相关的技术效果；
4. 弱化公式，强调物理数据流和控制流。

### 5.2 意见类型：Hypernetwork 已公开生成权重

答复方向：

1. 区分“生成权重”与“生成临时权重描述子块”；
2. 区分一般权重生成与片上存储器中的分块生成-消费-释放；
3. 强调不在外部存储器中物化完整稠密矩阵；
4. 强调全生命周期不回写外部存储器。

### 5.3 意见类型：低秩分解是公知常识

答复方向：

1. 同意低秩分解本身公知；
2. 强调本发明的创新点不在低秩数学本身，而在于其与运行时条件生成、片上转换、分块局部执行、不回写外存的组合。

### 5.4 意见类型：片上 SRAM 常驻权重方案已公开

答复方向：

1. 区分“预先分发的静态权重”与“运行时生成的临时权重描述子块”；
2. 强调本发明中的数据对象不是长期常驻权重，而是执行时即时生成并即时释放的对象；
3. 强调对应完整稠密矩阵不在外部存储器中形成。

### 5.5 意见类型：训练系统已公开梯度同步或优化器分片

答复方向：

1. 区分一般梯度压缩与本案的“与临时权重描述子块对应的局部梯度块不进入优化器状态且不参与同步”；
2. 强调触发前提是反向重算路径中的临时对象，而不是任意梯度；
3. 强调训练和前向由同一临时对象生命周期架构统一约束。

## 6. 建议保留的关键术语

答审和修改时尽量保持以下术语稳定：

1. `片上存储器`
2. `外部存储器`
3. `临时权重描述子块`
4. `临时目标权重分块`
5. `向量计算单元`
6. `矩阵计算单元`
7. `不回写`
8. `节点间高带宽通信总线`

不建议在不同文件中混用过多替代词，否则容易削弱支撑一致性。

---

## 7. 证据优先级

若希望把申请质量提升到更高水平，最值得补的证据依次为：

1. profiler 证明未回写 HBM/DRAM；
2. 外部存储器流量与稠密基线的对比；
3. 矩阵计算单元利用率和 stall 原因对比；
4. 自回归解码中 KV Cache 受益或上下文长度受益；
5. 分布式训练中的 All-Reduce 字节数或抓包证据；
6. 融合路径与参考路径的一致性；
7. 继续训练或蒸馏后的精度恢复。

## 9. 结论

本案如果想做到高质量，关键不是把文本写得更“玄”，而是让所有材料始终围绕同一个技术边界：

`运行时条件生成 + 临时权重描述子块 + 片上转换/消费 + 用后释放 + 全生命周期不回写 + 可选反向重算 + 可选通信豁免`

只要该边界在交底书、说明书、摘要、权利要求和检索分析中保持一致，本案的整体质量和答审韧性就会明显高于普通 AI 概念型申请。
