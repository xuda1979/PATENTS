# 专利技术交底书
# 面向存储带宽受限神经网络推理的即时临时元权重生成系统及方法

---

## 1. 交底目的

本交底书用于向专利代理人或内部法务说明本发明的技术背景、核心构思、实施方式、希望保护的重点以及与已知方案的主要区别，便于后续形成中国发明专利、PCT 或美案申请文本。

本交底书对应的技术代号为：`MWG-EW`（Meta-Weight Generation for On-the-Fly Ephemeral Weights）。

---

## 2. 技术名称

建议名称：

**一种面向存储带宽受限神经网络推理的即时临时元权重生成系统及方法**

备选名称：

1. 一种用于大模型推理的片上临时元权重生成与执行方法
2. 一种基于元生成器的神经网络临时权重 tile 生成与局部执行系统
3. 一种避免外存稠密权重实体化的神经网络推理方法

---

## 3. 技术领域

本发明涉及人工智能推理、神经网络加速、Transformer 模型压缩与执行优化领域，尤其涉及一种在推理阶段根据 token 特征和层标识实时生成权重描述子 tile，并仅在片上局部存储区域中完成生成、消费和释放，而不将对应完整稠密权重矩阵写回外部存储区域的神经网络推理系统及方法。

---

## 4. 背景技术与现有痛点

### 4.1 背景问题

在大语言模型和其他 Transformer 模型的自回归推理中，性能瓶颈通常不是矩阵乘法单元本身的算力，而是大量前馈网络（FFN）权重矩阵从外部显存或片外内存反复搬运到片上资源所造成的存储带宽压力。

特别是对于 FFN 的上投影、门控投影和下投影矩阵，其参数量很大，且在每层、每 token 推理过程中都需要重复参与计算。随着 GPU / NPU / TPU 的矩阵算力持续增强，外部存储带宽的提升相对较慢，导致大量计算单元等待权重而空转，即所谓 memory wall。

### 4.2 已知方案及不足

当前常见方案主要包括：

1. **量化**：减少每个权重的存储位宽，但仍需要读取外部存储中的权重。
2. **静态低秩分解**：将稠密矩阵拆分为较小因子，但因子本身仍是持久参数，推理时仍需读取。
3. **LoRA/Adapter 类方法**：主要服务于训练或微调阶段，重点不是推理期的权重搬运问题。
4. **MoE**：减少激活专家数，但被选中的专家权重仍需装载。
5. **kernel 融合与 IO-aware 算法**：能减少激活中间结果搬运，但通常默认权重本身已作为静态操作数存在。
6. **Hypernetwork/动态权重生成**：可以由一个网络生成另一个网络的参数，但通常没有把重点落在“片上 tile 级生成-消费-释放且不回写外存”的硬件执行生命周期上。

因此，现有方案大多只是在“如何更省地存权重”或者“如何更快地算激活”上做文章，尚未充分解决“推理时大量静态 FFN 权重反复经由外部存储搬运”的问题。

---

## 5. 发明要解决的技术问题

本发明要解决的核心技术问题是：

**如何在不依赖外部存储反复读取完整稠密投影矩阵的情况下，完成神经网络尤其是 Transformer 前馈网络的推理计算，从而降低外部存储流量，提高片上矩阵计算单元利用率。**

进一步而言，本发明希望实现以下目标：

1. 将部分推理路径从“存储带宽受限”转换为“局部计算受限”；
2. 避免在推理过程中把目标投影的完整稠密矩阵作为持久参数存在外部存储中参与读写；
3. 支持从现有预训练稠密模型迁移到该执行方案；
4. 支持 GPU、NPU、TPU、边缘设备及云端推理硬件。

---

## 6. 发明核心构思

本发明的核心构思不是单纯的低秩分解，也不是抽象意义上的“一个网络生成另一个网络的权重”，而是如下闭环：

`条件输入 -> 元生成器按需生成权重描述子 tile -> 将 tile 放入片上局部存储 -> 通过结合式矩阵分解执行计算 -> 输出累积 -> 释放或覆写 tile -> 不回写外部存储`

其中：

1. 条件输入至少包括 token 相关特征表示和层标识；
2. 元生成器生成的不是必须长期存储的完整稠密权重，而是临时的权重描述子 tile；
3. 这些权重描述子 tile 可以是低秩因子，也可以是用于重构低秩因子的基系数；
4. 计算采用例如 `Y = (XU)V` 这类结合式分解，避免在外部存储中实体化完整矩阵 `UV`；
5. 生成的权重描述子仅在寄存器、共享内存、SRAM、缓存等片上局部存储中短暂存在；
6. 使用后立即释放、覆写或清零，不将其作为持久模型权重写回外部存储。

---

## 7. 技术方案概述

### 7.1 系统方案

系统至少包括：

1. **加速器**：包括矩阵计算单元、片上局部存储区域、外部存储区域；
2. **条件模块**：用于形成条件信号；
3. **元生成器**：根据条件信号生成权重描述子 tile；
4. **融合执行引擎**：在片上局部存储中消费权重描述子 tile，并通过结合式矩阵分解完成线性变换；
5. **存储生命周期控制器**：控制权重描述子 tile 的创建、保留时间、释放、覆写或清零，并阻止其回写至外部存储区域；
6. **可选调度器**：在动态生成权重路径与静态权重路径之间按层、按 token 或按 batch 切换。

### 7.2 方法方案

方法可包括如下步骤：

1. 接收当前推理步骤的激活张量；
2. 从激活张量中提取 token 特征，并结合层标识形成条件信号；
3. 由元生成器生成目标投影对应的权重描述子 tile；
4. 将该 tile 仅存储在片上局部存储中；
5. 对该 tile 执行局部矩阵乘法并累积部分输出；
6. 在生成下一个 tile 之前释放、覆写或清零当前 tile；
7. 不将该 tile 作为模型权重写回外部存储。

---

## 8. 关键技术特征

建议代理人在起草时将下列特征视为核心：

### 8.1 条件生成

条件信号至少包括：

1. token 相关特征表示；
2. 层标识。

可选再包括：

1. 位置编码；
2. 路由摘要；
3. 任务标识；
4. 域标识；
5. 硬件运行状态或带宽配置。

### 8.2 权重描述子而非完整稠密权重

元生成器输出优选为：

1. 低秩因子 tile `U` 与 `V`；
2. 基库系数，由执行引擎在片上重构出 `U` 与 `V`；
3. 其他不足以直接构成完整外存持久稠密矩阵的临时描述子。

### 8.3 结合式执行

对于目标变换 `W_eff`，不直接将 `W_eff` 作为完整矩阵读出，而是采用：

`W_eff ~= UV`

并执行：

`Y = (XU)V`

对于门控 FFN，可采用：

`A = phi((XU_up)V_up)`

`G = psi((XU_gate)V_gate)`

`Y = ((A .* G)U_down)V_down`

### 8.4 片上局部存储生命周期

权重描述子 tile：

1. 生成后仅进入片上局部存储；
2. 仅在局部存储驻留期间被消费；
3. 消费完后立即释放或覆写；
4. 不回写外部存储，不形成持久模型权重。

### 8.5 tile 级执行

优选地，本发明以 tile 为基本处理粒度：

1. 生成一个 tile；
2. 计算一个 tile；
3. 累积输出；
4. 释放当前 tile；
5. 再进入下一个 tile。

### 8.6 融合 kernel

优选由单个融合 kernel 完成：

1. 条件处理；
2. 权重描述子 tile 生成；
3. 局部存储放置；
4. 矩阵计算；
5. 输出累积；
6. 生命周期结束处理。

## 9. 优选实施方式

### 9.1 实施方式 A：直接生成低秩因子 tile

元生成器直接输出 FFN 中上投影、门控投影和下投影对应的 `U/V` 因子 tile。

### 9.2 实施方式 B：基库重构

元生成器只输出基系数，实际低秩因子在片上局部存储区域内由基库组合重构。

### 9.3 实施方式 C：部分层替换

仅将最耗带宽的一部分 FFN 层替换为动态生成路径，其他层仍保留静态权重。

### 9.4 实施方式 D：自适应秩

秩 `r` 根据 token 复杂度、带宽预算、时延目标、层深度或矩阵计算单元占用率动态调节。

### 9.5 实施方式 E：分组 token 复用

在保持非持久的前提下，对于条件信号相近的一组 token，在短时间窗口内复用部分权重描述子。

### 9.6 实施方式 F：从预训练稠密模型迁移

从现有稠密模型出发：

1. 选择目标 FFN 投影；
2. 插入元生成器和融合执行路径；
3. 冻结部分原参数；
4. 通过继续训练或蒸馏恢复性能。

## 10. 相对于现有技术的主要区别

### 10.1 与 Hypernetwork 的区别

现有 Hypernetwork 主要强调“网络生成网络参数”，本发明强调：

1. 推理时生成；
2. 生成对象是权重描述子 tile，而非必须持久保存的完整权重；
3. 权重描述子仅驻留于片上局部存储；
4. 使用后不回写外部存储；
5. 与 tile 级融合执行路径绑定。

### 10.2 与 LoRA / 低秩适配的区别

现有 LoRA/低秩适配主要是：

1. 静态低秩矩阵；
2. 面向训练/微调；
3. 推理时仍默认使用持久参数。

本发明则强调：

1. 推理时按需生成；
2. 生成的是临时权重描述子；
3. 推理路径中避免完整稠密矩阵在外部存储中实体化。

### 10.3 与 FlashAttention / IO-aware kernel 的区别

现有 IO-aware kernel 主要减少激活和注意力中间结果的 HBM 访问。本发明进一步把 IO-aware 思路前移到**权重本身的创建与生命周期管理**，目标是减少 FFN 权重搬运。

### 10.4 与参数驻片加速器的区别

现有“weights resident on chip”类方案通常仍以**预先分发的静态权重**为前提，本发明强调的是：

1. 权重是运行时生成的；
2. 生成后临时存在于片上；
3. 用完销毁；
4. 不再视为静态模型参数。

## 11. 预期技术效果

本发明预期可获得以下技术效果：

1. 降低目标投影的外部存储读取流量；
2. 避免完整稠密矩阵 `UV` 的外存实体化；
3. 提高矩阵计算单元利用率；
4. 降低大模型在带宽受限设备上的部署门槛；
5. 支持更灵活的动态/静态混合推理。

---

## 12. 希望重点保护的内容

建议优先保护以下内容：

### 12.1 第一优先级

1. 基于 token 特征和层标识生成权重描述子 tile；
2. 通过结合式矩阵分解执行线性变换；
3. 权重描述子仅在片上局部存储区域内存在；
4. 使用后释放且不回写外部存储。

### 12.2 第二优先级

1. FFN 上投影/门控投影/下投影场景；
2. 单 kernel 融合生成-计算-释放；
3. tile 级生命周期控制；
4. 基库系数重构；
5. 自适应秩选择。

### 12.3 第三优先级

1. 分组 token 复用；
2. 与静态权重路径混合调度；
3. 从稠密预训练模型迁移的训练流水线。

## 15. 交底结论

本发明最有价值的保护点不是“动态生成权重”这一抽象概念本身，而是以下组合：

1. 运行时条件生成；
2. 低秩或等价权重描述子；
3. 结合式矩阵执行；
4. tile 级片上局部驻留；
5. 用后释放且不回写外部存储。

建议后续权利要求撰写围绕该组合展开，以系统/方法/存储介质三类独立权利要求为基础，再向 FFN、基库重构、自适应秩、单 kernel、迁移训练等方向铺设从属权利要求。
